How we classify

What each automated field actually checks, in plain terms.

Seniority

Five tiers: free from the title first, AI from the description second

Every scraped job gets a seniority guess (Entry, Junior, Mid, Senior, or C-Level) computed fresh from its title by src/seniority.js in the scraper. No AI call, no cost: it's pattern matching against English and Danish signal words, checked in this order (most specific first, so "Senior Software Engineering Intern" resolves to Entry, not Senior):

  • C-Level: CEO/CFO/COO/CTO/CIO/CMO/CHRO/CPO/CCO, "Chief … Officer", President, Managing Director, Danish "Adm. Direktør".
  • Entry: intern, internship, trainee, graduate, apprentice, entry-level, working/student assistant, and Danish elev/praktikant/fritidsjob/sommerjob (including compounds like "Kontorelev" with no space).
  • Junior: junior, jr.
  • Senior: senior, sr., lead, principal, head of, director, VP/vice president, manager, and Danish "chef" (e.g. "Salgschef": manager, not the English "cook").
  • Mid: only an explicit "mid-level"/"mid level" in the title.

If nothing matches, it falls back to whatever the source site itself reported (only two of nine sites provide this). If that's still empty and this job has a full description (jobnet.dk today), the same AI call described under Language below is also asked for a seniority read — only when the description states one explicitly (years of experience, an explicit level word, "leads a team of X", "reports to the COO"), never guessed from tone or responsibilities. Title-only jobs skip this entirely: there's nothing new for the AI to read there that the regex hasn't already seen. Still empty after both? Left blank rather than guessed further — a wrong guess is worse than an honest blank (see the Missing Data tab).

Language

An AI call, not a fixed algorithm

Language detection isn't a hand-written rule set like Seniority's title-regex layer is: it's one question inside the same Claude Haiku 4.5 call that also generates Tags and checks whether a listing is a real job (classifyJob() in src/anthropic.js). The model is asked for the two-letter ISO 639-1 code of the language the job title (and company name, if it helps) is written in, and returns null if it can't tell, never a guess.

Because it rides on a call that's already happening for Tags/job-verification, it costs nothing extra beyond that one call. Seniority's AI supplement (see above) rides on the same call too, when a description is available.

Language Requirement / Bonus

Two more questions on the same AI call

Also part of classifyJob(), not a separate call. Language Requirement is a language the title states as a hard requirement for the candidate (e.g. "Danish-speaking Sales Manager" or "Tysktalende Kundeservicemedarbejder" implies one). Language Bonus is a language mentioned as merely nice-to-have (e.g. "German is a plus"). Both are plain language names, not codes, and both are null unless the title actually states one: most titles state neither, and neither is inferred from the ad's own language (that's the separate Language field above) or from the job's country.
